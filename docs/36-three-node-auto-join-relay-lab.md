# 36. Three-node automatic Join and relay LAB

状態: **Proposed — private LAB implementation profile**  
ADR: [ADR-0037](adr/0037-three-node-auto-join-relay-lab.md)

This profile closes one narrow hardware question: can three identical
ESP32-S3 + SX1262 boards discover a site, Join without per-node radio
configuration, forward an ApplicationData packet through a relay, and recover
when the selected parent disappears?

It is deliberately not Production Attachment, public ABI, or a replacement
for the accepted RRMP contracts.

## 1. Fixed scope

- Every board runs the same image and derives a stable 64-bit LAB node ID from
  its ESP32-S3 factory MAC.
- One board is promoted to controller through the USB console. Other boards
  start unjoined and discover it over radio.
- Joined non-controller boards also advertise as relay candidates. A node is
  not fixed to one endpoint/relay role.
- Join, uplink/downlink data, bounded duplicate suppression, route expiry,
  parent reselection, and site lease expiry are exercised over the real
  Ninlil R5 permit -> R1 HAL -> R9 -> SX1262 path.
- Application payload is opaque 1..64 bytes.
- Maximum route depth is three hops; the first HIL uses three boards and two
  physical transmissions per direction.

## 2. Honest boundary

`NJM1` is unauthenticated LAB control traffic. It MUST NOT create or claim a
Production Site Membership, EDHOC Attachment, secure Route Lease, or legal
deployment approval. Production Attachment remains governed by chapter 35.

The LAB image fixes its RF plan to 923.0 MHz, 125 kHz, SF7, CR 4/5, 8-symbol
preamble and 10 dBm, and keeps the existing CAD/LBT and R5 permit path. This is
a conservative test configuration, not a legal conclusion. The operator must
still verify the module certification mark, approved antenna, installation,
and applicable Japanese rules before transmitting.

## 3. Join and relocation

Controller beacons carry a random non-zero site ID and a random non-zero
site-instance epoch. This private LAB discriminator is not persistent or
monotonic across reboot; no NVS lifecycle claim is made. A joined relay repeats
reachability in its own beacon.

An unjoined node:

1. collects valid beacons;
2. selects the lowest-cost parent;
3. sends `JOIN_REQUEST` toward the controller;
4. becomes joined only after `JOIN_ACCEPT` returns through the learned reverse
   path.

A joined node accepts only its current site and epoch while its lease is
valid. Parent loss starts reselection inside that site. If no route exists
until the lease expires, the node clears the old LAB membership and may Join a
new site. USB `LEAVE` performs the same clearing explicitly. This models
removal and installation at another site without treating two live sites as
one authority.

## 4. Route choice

Lower score wins:

`32 * resulting_hops + RSSI_penalty + advertised_load + test_penalty`

The current parent is retained unless another candidate is at least 12 points
better and has been observed twice. Candidates and the selected parent expire
only after 12 seconds, covering at least three roughly-3-second beacon
opportunities. Route leases remain 20 seconds. A new Join attempt gets a new
sequence.

Before its first Join, a node waits a bounded 10-second discovery window from
the first valid beacon, then selects the best mature candidate. The window
covers three to four real relay beacon opportunities while remaining below the
12-second candidate expiry. This prevents a first-arriving direct controller
from being committed before a better relay is heard, while a single available
parent still joins after the window.

Controller beacons get a bounded, deterministic 0..700 ms jitter derived from
the complete stable NJM1 node ID and that beacon's sequence. A joined relay
does not free-run a competing cadence: after each valid selected-parent beacon
it emits one child beacon 500 ms later. This makes its advertisement evidence
of parent reception and prevents repeating controller/relay collisions; it is
not an unbounded random MAC backoff or TDMA framework.

For a current-site membership, a parent candidate MUST advertise strictly
fewer controller hops than the node's current hop count. Thus a hop-2 endpoint
may choose a hop-1 relay, but a hop-1 relay cannot choose that hop-2 endpoint
as its parent. This upstream-only rule remains in force after parent loss
until lease expiry clears the old membership, preventing equal/downstream
reselection loops.

Every response or relay frame generated by an RX completion waits a fixed
225 ms half-duplex turnaround guard before it may enter the permit/TX path.
The pending response has priority over a new receive arm during that bounded
interval. The conservative LAB allowance covers RX-complete polling, main-loop
scheduling, and bounded diagnostic output before the prior sender returns to
RX; it is LAB timing, not a production MAC claim.

After a successful non-beacon transmission, the NJM1 app suppresses periodic
beacon scheduling for a bounded 1.5-second forwarding/response dwell and
re-arms RX. For `JOIN_REQUEST` and `DATA` this protects the expected
`JOIN_ACCEPT` or `ACK`; for a forwarded `JOIN_ACCEPT` or `ACK` it prevents an
immediately due beacon from colliding with the next downstream hop. Incoming
frames continue to be processed during the dwell. It is private LAB timing,
not a generic retransmission or production MAC mechanism.

For a locally originated `DATA`, an `ACK` carrying that DATA's origin
sequence completes the send. A joined sender stages its first DATA 500 ms
after its selected parent's next beacon, when that parent has completed its
beacon TX and has returned to RX. If no matching ACK arrives, the LAB app
keeps RX armed for a 3-second ACK wait plus a deterministic
0..700 ms retry jitter derived from the source ID, origin sequence, and
attempt. That bound covers
the two-hop LAB return path's two 225 ms guards, airtime, main-loop polling,
and diagnostic output; it is separate from the 1.5-second JOIN response
dwell. Only then does it retransmit the payload with a fresh origin sequence
at most twice (three RF attempts total), then reports
`MESH data_drop ... ack_timeout`. A fresh sequence lets an earlier lost relay
forward remain recoverable without weakening duplicate rejection. Relays never
perform this ACK-wait retry; they forward once, so the bound does not amplify
traffic.

`test_penalty` is a visible HIL-only control used on a desk where every radio
can hear every other radio. `MESH PENALTY <node> 0..199` adds that ordinary
score penalty. `MESH PENALTY <node> 200` explicitly excludes that candidate:
the node waits for another mature candidate instead of silently falling back
to it, including during hysteresis-based reparenting. Console output reports
`mode=score` or `mode=exclude`. This changes
logical HIL topology only and never claims RF isolation or range. Reset to
`0` before testing direct fallback. Two genuinely independent relay choices
require four or more boards.

## 5. NJM1 frame

All integers are big-endian. Total length is 64..128 bytes.

| Offset | Bytes | Meaning |
| ---: | ---: | --- |
| 0 | 4 | ASCII `NJM1` |
| 4 | 1 | version, exactly 1 |
| 5 | 1 | kind |
| 6 | 1 | flags, zero |
| 7 | 1 | remaining hops / advertised controller distance |
| 8 | 8 | LAB site ID |
| 16 | 4 | site epoch |
| 20 | 4 | origin sequence |
| 24 | 8 | original source node |
| 32 | 8 | current transmitting node |
| 40 | 8 | next hop; zero only for beacon |
| 48 | 8 | final destination; zero only for beacon |
| 56 | 1 | payload length, 0..64 |
| 57 | 1 | advertised load, 0..100 |
| 58 | 2 | zero |
| 60 | n | payload |
| 60+n | 4 | CRC32C of all preceding bytes |

Kinds are `BEACON=1`, `JOIN_REQUEST=2`, `JOIN_ACCEPT=3`, `DATA=4`, and
`ACK=5`. Receivers reject invalid version, flags, reserved bytes, length, CRC,
zero mandatory IDs, wrong site/epoch, wrong next hop, duplicate tuple, or
exhausted hop count before mutating route state.

Every accepted non-beacon frame learns `original source -> current
transmitter` as a bounded reverse route. A relay changes only `current
transmitter`, `next hop`, and remaining hops. It does not change source,
destination, sequence, site, epoch, or payload.

## 6. Acceptance

Host simulation must show:

1. controller + relay + endpoint automatic Join;
2. endpoint uplink and controller downlink through the relay;
3. duplicate suppression and hop-limit rejection;
4. relay loss followed by automatic direct-parent selection;
5. old-site lease expiry followed by Join to a different site.
6. a hop-1 relay rejecting a hop-2 endpoint as a parent while the endpoint
   remains allowed to select that relay.

Hardware evidence must record three distinct board IDs, transmitted and
received frame counters, selected parents, hop counts, RSSI/SNR, Join state,
route changes, and RF configuration. A shared-desk logical topology is reported
as such and is not range or obstruction evidence.

## 7. macOS Mesh LAB Console

The private dependency-free Python console scans `/dev/cu.usbmodem*` and can
attach all eight LAB boards at 115200 baud. USB is an observation and command
plane: once per second it requests `MESH STATUS` from each attached board and
uses each board's local parent snapshot to draw the live tree. This does not
add topology chatter to the RF channel. The HTTP server binds only to
`127.0.0.1` and state-changing requests require a process-local token.

The UI includes:

1. live parent edges, hop depth, Join state, lease and route-change counters;
2. node health, last USB observation, and the most recently reported RX
   RSSI/SNR;
3. one-at-a-time controller-to-node Ping/Pong probes, where Pong is the
   existing correlated DATA ACK and RTT includes queueing, RF transmission,
   relay forwarding, ACK forwarding, and retries;
4. a bounded eight-node sweep that requires one visible Controller and seven
   joined nodes before it starts;
5. an explicit Demo mode (`--demo`) that sends no serial or RF commands.

The route displayed for a probe is inferred from contemporaneous parent
snapshots; it is not an on-wire packet trace. Per-hop RTT, RF-only last-seen,
channel occupancy, automatic SF/channel/power tuning, and eight-board HIL
evidence are not claimed by this console.

Run from source:

```sh
python3 tools/ninlil_lab_console.py
```

Preview the deterministic eight-node UI without hardware:

```sh
python3 tools/ninlil_lab_console.py --demo
```

Or generate the local macOS application bundle:

```sh
tools/package_ninlil_lab_console_macos.sh
open "dist/Ninlil LAB Console.app"
```

The generated `dist/` tree is intentionally not source-controlled. Python 3
must be installed on the Mac. This console is a LAB operator tool, not a
production Controller or provisioning authority.
